An in-place upgrade to RabbitMQ 4.3 or later would silently empty 37 classic queues
These queues use the old classic queue index (version 1), which is the 3.13 default. RabbitMQ 4.3 and later cannot read it. The loss cannot be detected after the upgrade. A definitions file cannot tell the index version, so this list is every classic queue without "x-queue-version: 2".
orders, orders-retry, invoices, billing.events, ... (first 10 of 37)
check_circle
Recommended: do not upgrade in place
Build a new 4.x broker, apply the migration this screen generates, then move the messages with a Shovel. A Shovel does not read the old index.
Other ways, done by hand and not offered by this app: set the policy "queue-version: 2" and restart the node gracefully, then check that every queue shows version 2; or upgrade through 4.0, 4.1 or 4.2 first.
