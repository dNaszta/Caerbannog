# M9-14 spike results: what the topology export may rely on, measured

Measured on 2026-11-16 on a throwaway Testcontainers broker, Docker Desktop on an Apple-silicon Mac (aarch64 image): `rabbitmq:4-management` = **RabbitMQ 4.4.0**, Erlang **29.1.2**, management plugin 4.4.0, plugins `rabbitmq_stream`, `rabbitmq_stream_management`, `rabbitmq_mqtt`. The tag floats: a newer 4.x that answers differently fails the spike on purpose. Users are throwaway (`guest` of the container and `m914-*`); no secret is in any fixture.

Living proof (tag `broker`): `RealBrokerM9ExportSpikeTest` (E0 to E7a, 11 tests), run with `./gradlew :data-rabbit:brokerTest --tests '*RealBrokerM9ExportSpikeTest*'`. Raw answers: `data-rabbit/src/test/resources/fixtures/m9-14/` (written when the environment variable `RECORD_M9_14_FIXTURES` is set). Status at step 2: **E0 to E6 and E7a pass (9 of 9 measured); E7 (the gate) is RED on purpose**: the exporter drops what is measured below.

## Read first: contradictions and surprises

1. **The export drops streams completely today, not only their retention.** `TopologyCatalog.queues` never returns a stream (documented, tested), so `exportCurrentTopology` never sees one: a super stream's exchange and bindings are exported, its partition streams are not, and a plain stream is not either. The brief assumes streams are exported by name (`DeclareStream`, "retention left out"). The queue list the broker gives DOES hold the streams (E1), so the new read must include them. The tests fix a new read for it (see "API shape" in the report).
2. **MQTT subscription queues are not recognisable by one flag.** QoS 0 queue: type `rabbit_mqtt_qos0_queue`, exclusive true. QoS 1 clean session: classic, exclusive true. QoS 1 persistent session: classic, durable, **exclusive false**, argument `x-expires` 86400000. Only the name (`mqtt-subscription-` prefix) catches the persistent one. Rule the tests fix: leave out `exclusive == true`, names starting `amq.gen-`, names starting `mqtt-subscription-`.
3. **A non-durable queue exists only on a broker that still permits the deprecated feature `transient_nonexcl_queues`** (E1b: 201, `durable` false, `auto_delete` true). A default 4.x refuses to declare one (E1, E3: HTTP 400, the executor says "the broker refused the request", nothing is created). So an export of such a broker would write a file that cannot be applied to a default 4.x. The tests fix: a non-durable, non-exclusive queue is left out and named ("transient") in the result line. The brief says "exclusive and transient queues named": this is the reading; the architect confirms.
4. **Operator policies are NOT in `GET /api/policies/{vhost}`** but in `GET /api/operator-policies/{vhost}`, same fields; and every user with a permission on the vhost reads both (E6). The brief puts operator policies out of scope "unless the spike shows they are needed for equality". They are needed for equality (a vhost with one differs after the round trip), and the read is as cheap as the policy read, so the tests include them (`operatorPolicies`). The architect decides; the cost of dropping them is two tests, one scenario and the operator policy of E7.
5. **E6 shows no permission wall.** `management`, `monitoring`, `management,policymaker` and plain `policymaker` users all got 200 for both lists. The only refusal is a vhost the user has no permission on: **404** (not 403). The "unreadable policies fail loudly" rule therefore means: any non-success of the policy read (NotFound, NotAuthorised, Unreachable, Unexpected) fails the export with the existing message. Nobody is excluded by tag.
6. **Super stream partitions carry an argument the export cannot keep.** The CLI (`rabbitmq-streams add_super_stream`) gives every partition stream `x-queue-leader-locator: balanced`. `DeclareStream` has no arguments, so that argument is left out together with retention. A replay still gives a working super stream (E5).
7. **Whole numbers stay whole, decimals stay decimals, booleans stay booleans** in every list (E1, E4, E6); the one trap is `x-max-age` and a policy's `max-age`, which are TEXT (`7D`, `1D`). `x-stream-partition-order` is a number.
8. **Order of the file does not matter to the broker** (E7a): exchanges, queues, bindings, policies; queues, exchanges, bindings, policies; and policies first all give the same topology. The only rule is that a binding needs both its ends first (bindings first: 8 of 24 actions failed). So the byte-for-byte rule for a topology without new things costs nothing: keep today's order (queues, exchanges, bindings) and append streams, then policies; the brief's order "exchanges, queues, bindings, policies" is a choice, not a need. The tests fix only: bindings after every queue, exchange and stream; policies last.

## E0: the broker

Measured: version, Erlang, management version and architecture above (`fixtures/m9-14/overview-versions.json`). The first test asserts `rabbitmq_version` starts with `4.`.

## E1: queue list columns and types (`GET /api/queues/{vhost}?page=1&page_size=500&columns=name,type,durable,auto_delete,exclusive,arguments`)

- **Measured.** The broker honours the column list exactly: every item has precisely `arguments, auto_delete, durable, exclusive, name, type` and nothing else; the page fields are `filtered_count, item_count, items, page, page_count, page_size, total_count`. Streams ARE in the list. `durable`, `auto_delete`, `exclusive` are JSON booleans.
- Types (`fixtures/m9-14/e1-queues-columns.json`): classic `x-message-ttl` 60000, `x-max-length` 1000, `x-max-priority` 5 are numbers; `x-dead-letter-exchange` and `x-overflow` are text. Quorum `x-delivery-limit` 5 and `x-max-length` 100 numbers, dead-letter exchange text. Stream `x-max-age` is the TEXT `7D`, `x-max-length-bytes` 1000000000 a number.
- Flags: classic/quorum/stream declared normally: durable true, auto_delete false, exclusive false. Exclusive named queue (AMQP): type classic, durable false, auto_delete false, exclusive true. Server-named (`amq.gen-...`, exclusive auto-delete): durable false, auto_delete true, exclusive true.
- Non-durable auto-delete classic over HTTP on a default 4.x: **400** `Feature transient_nonexcl_queues is deprecated. By default, this feature is not permitted anymore.` (E1b: on a broker with `deprecated_features.permit.transient_nonexcl_queues = true` in `conf.d`: 201, row `type classic, durable false, auto_delete true, exclusive false, arguments {x-queue-type: classic}`).

## E2: what the broker adds by itself

- **Measured.** For classic (with and without an explicit `x-queue-type`), quorum and stream queues declared with no other argument, `arguments` is exactly `{"x-queue-type": "<type>"}`: the broker adds **nothing else** (no `x-queue-version`, no storage field). A classic queue declared with no `x-queue-type` also says `x-queue-type: classic`. A policy never shows in `arguments` (policy `max-length` on a queue: arguments unchanged). The single-queue object has other keys (`consumer_details, deliveries, garbage_collection, incoming, internal, internal_owner, leader, members, node, online, state, vhost`), none of them from the declaration.
- **Rule for the code:** the only argument never exported is `x-queue-type` (it is the `type` key; the parser refuses it in a file).

## E3: what an export leaves out

- **Measured.** Exclusive and server-named queues: `exclusive: true` in the list. MQTT (rabbit_mqtt, default vhost, clean-session clients stay connected, persistent client disconnected): see surprise 2. The persistent session queue stays listed after its client left (name `mqtt-subscription-<clientid>qos1`, durable, x-expires 86400000). The single-queue object has no owner field (`owner_pid_details` null): nothing else tells an MQTT queue apart.
- `declareQueue` through the real executor on a default 4.x: non-durable → Failed ("the broker refused the request"), 404 after; non-durable + auto-delete → same; **durable + auto-delete classic → Success** (200 after); durable + auto-delete quorum → Failed. (M8-00 found the same for a definitions import, where the queue was silently not created; through `PUT /api/queues` the broker says 400 loudly.)
- **Rule for the code:** leave out `exclusive`, `amq.gen-*`, `mqtt-subscription-*`, and non-durable queues; name exclusive and non-durable ones (transient) in the result line.

## E4: exchanges and bindings

- **Measured.** Exchange keys: `arguments, auto_delete, durable, internal, name, type, user_who_performed_action, vhost`. `alternate-exchange` text; `x-super-stream` JSON boolean true; `internal` true for an internal exchange; a non-durable auto-delete exchange keeps both flags. Built-in exchanges listed: the default `""`, `amq.direct`, `amq.fanout`, `amq.headers`, `amq.match`, `amq.rabbitmq.trace`, `amq.topic`.
- Headers binding arguments: `{"level":3,"ratio":1.5,"region":"eu","urgent":true,"x-match":"all"}`: whole number stays a number, decimal a number, boolean boolean, text text. Binding keys: `arguments, destination, destination_type, properties_key, routing_key, source, vhost`. A user binding on `amq.topic` IS listed (source `amq.topic`, destination the user queue); the implicit default-exchange binding of every queue is listed too (source `""`). Exchange-to-exchange: `destination_type` `exchange`. `x-stream-partition-order` is a number. An empty routing key has a `properties_key` like `~5rXldQ` (hash of the arguments).
- **Rule for the code:** keep the typed arguments as `ArgumentValue`; export user bindings on built-in exchanges (not the exchange); drop source `""`.

## E5: a super stream

- **Measured** (CLI `rabbitmq-streams add_super_stream orders --partitions 3`; the stream-protocol creator makes the same shape per M2-07): exchange `orders` type `direct`, durable, not internal, arguments `{"x-super-stream": true}`; partition streams `orders-0..2` (type stream, durable, arguments `{"x-queue-leader-locator":"balanced","x-queue-type":"stream"}`); bindings `orders` to `orders-i` with routing key `i` and arguments `{"x-stream-partition-order": i}` (number).
- **Replay.** The reference conversion of this spike (raw lists to actions, `DeclareStream` without arguments, bindings with typed arguments) was applied with the real executor on an empty vhost: every action succeeded; the replayed exchange has `x-super-stream: true`, the same three streams exist, the bindings are equal including `x-stream-partition-order`. Not kept: the partitions' `x-queue-leader-locator` (see surprise 6).

## E6: policies

- **Measured.** `GET /api/policies/{vhost}` item keys: `apply-to, definition, name, pattern, priority, vhost`. `priority` is a JSON number (negative values kept, `-1`); `apply-to` text (`queues`, `streams`, `all`); definition values: `max-length`, `message-ttl`, `delivery-limit`, `stream-max-segment-size-bytes` numbers; `dead-letter-exchange`, `overflow`, `max-age`, `queue-leader-locator` text. Operator policy: not in `/api/policies`; `GET /api/operator-policies/{vhost}` has the same keys; it is also a parameter `operator_policy` (`/api/parameters/operator_policy/{vhost}`, wrapped in `value`), which is what the definitions export shows (M8-00 S-A).
- Permissions: users with tags `management`, `monitoring`, `management,policymaker`, `policymaker` (each with a permission on the vhost) all got 200 for both lists. A `management` user with no permission on the vhost got **404** `Not Found`.

## E7: the round trip (the live gate), and E7a (order)

- **E7a measured (passes).** Seeded vhost: 7 exported queues and streams, 6 exchanges, 8 bindings, 2 policies, 1 operator policy (and the exclusive and server-named queues, left out). The reference conversion applied in three orders gave 24 actions, 0 failures, an identical snapshot each time (surprise 8); bindings first: 8 of 24 failed.
- **E7 (RED, as designed).** Today's export of the same vhost has **19 actions: 5 declareQueue, 6 declareExchange, 8 declareBinding**, no policy, no stream, and the exclusive queue `q-exclusive` and the server-named queue ARE in it. The first assertion that fails is "policies come last" (none exist); behind it still wait the stream and super stream partitions, the arguments, the exclusion, the round trip to the empty broker B, and the second export. It goes green only when the exporter keeps them all.
