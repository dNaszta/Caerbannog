# M5-08a: management executor, conflicts, read-back and rerun safety

Milestone: M5    Depends on: M8-04 (merged), M5-07 (merged)    Size: M    Umbrella: `M5-08-real-migration-execution` (decisions, rerun table, scenario ownership)

## Goal
A migration is applied to a real 4.x broker by a real executor: each action is sent, read back, never overwrites anything with other settings, and a rerun after a failure is safe. No UI, no persistence, no folder (those are `M5-08b` and `M5-08c`).

## Why
No real executor exists (umbrella "Why"). Owner decision 2026-11-09: option A and "make rerun safe". CLAUDE.md: only the migration executor may send management PUT or DELETE, with a path allow-list; never `/get`, `/contents`, `/purge`; delete only with the Full control level.

## Scope
In:
1. **`ManagementHttp`** (`data-rabbit`, internal): add `put(url, body)` and `delete(url)`. Do not copy the 60-line catch ladder of `get`/`post`: extract one private `send(block)` that holds the transport rules (TLS per profile, D9a, no credential before the profile was chosen, classification of `SSLException`, timeouts, `IOException`, never a copied body) and let the four verbs use it. A source-grep guard test lists the callers of `put` and `delete` and fails for any other class than the migration executor.
2. **`ManagementTopologyMigrationExecutor`** (implements `TopologyMigrationExecutor`): per action as in the umbrella table. Requests come from `MigrationRequests.requestFor` (M8-04) for declares; deletes and the policy read are built in a sibling `MigrationDeleteRequests` with the same encoding rules (`ManagementRequests.encode`, dot-only segments as `%2E`). Split by concern, composed by the executor: `MigrationWriter` (send and map the status), `ConflictCheck` (policy equality: pattern, apply-to, priority, definition with numeric comparison, key order irrelevant), `ReadBack` (verify; one retry after a delay (`RETRY_DELAY_MILLIS = 500`, a named constant, passed through an injected `suspend (Long) -> Unit`)). Statuses map to success or a FIXED reason (confirmed at step 2): 400 without `PRECONDITION_FAILED`, 404 on a declare, 409 and 3xx give "the broker refused the request"; `Unreachable`, `CertificateRejected` and `NoTlsAnswer` give "the broker did not answer". 400 precondition gives "<name> exists with different settings" (the name only when it passes the one echo rule below); 401 and 403 "not allowed"; 404 on a delete is success; 5xx and timeouts "the broker did not answer"; the broker's body is never copied. Streams (`declareStream`, `deleteStream`) call the held connection's `StreamManager`; an "already exists" refusal is a no-op; the read-back is the stream list.
3. **Path allow-list.** The executor can only produce requests to `/api/queues/`, `/api/exchanges/`, `/api/bindings/`, `/api/policies/`, `/api/operator-policies/` (and `GET`s of the same for read-back and the policy read); a test asserts it for every action x every hostile name (the 24 hostile names of the M8-04 verify) and that every path has exactly one of the documented SHAPES (`/api/{queues|exchanges|policies|operator-policies}/{vhost}/{name}`: three segments after `/api`; `/api/bindings/{vhost}/e/{source}/{q|e}/{destination}`: six, and seven with the properties key on delete), so a name can only ever stand in a name position and no suffix such as `/get`, `/contents` or `/purge` can follow it; no raw dot segment or slash from input. A queue literally named `get`, `contents` or `purge` is allowed (it is a name; the path stays `/api/queues/{vhost}/get`).
4. **`HeldConnection.migrationExecutor`**: `val migrationExecutor: TopologyMigrationExecutor? get() = null` on the interface (default null, like `manager`), implemented by the real gateway for a connection, exposed through `StreamSource` behind a guard that returns a refusing executor once the connection is no longer the current one (the pattern of `GuardedStreamManager`). A 3.x source keeps null: `M8-02` makes the detection; until then every connection gets one.
5. **Runner (`core`).** `MigrationRunner.dryRun` and `applyPending` take the connection's virtual host and BLOCK every action whose `vhost` differs: reason "The action belongs to virtual host <v>; this connection is for <c>" (the name only when short and plain). The level and permission checks stay. A `Failed` result stops the run, is reported as `ActionFailed(version, action, index, total, reason)` (add `index` and `total`, additive) and the migration is not recorded.
6. **File-level rerun rule (`core` parser).** `MigrationParser.parse` refuses a file that declares and deletes the same item (queue, exchange, stream, policy by kind, vhost and name; binding by vhost, source, destination and routing key): `Invalid("the file declares and deletes \"<name>\"; split it into two migrations")` (generic wording without the name when it is not short and plain). Implemented as one small `RerunSafety` check after the actions are read. If an existing test or fixture has such a file, the architect decides at step 2 (expected: none).
7. **Export (`MigrationsViewModel.exportCurrentTopology`).** Read every queue page (until `QueuePage.page == pageCount`); a failed catalog call (`NotAuthorised`, `Unreachable`, `Unexpected`, `BadPaging`) sets `state.errorMessage` to "The topology could not be read" and NO file is written (today it silently writes an empty migration). Safe API (decided at step 2): the return type becomes `MigrationFile?` (null when it failed); it never throws, so the bare `scope.launch` in `Main.kt` is safe without waiting for `M5-08c`. The two old call sites (`MigrationsViewModelTest` line about 331 and `TopologyMigrationsSteps` line about 410) change mechanically (`!!` or a null check): an allowed refactor, no assertion changes.
7b. **View model.** `isApplyPendingEnabled` and `isApplySingleEnabled` are false when the selected migration's dry run is blocked, including an action for another virtual host (core logic belongs here; the screen text and states are `M5-08c`). `MigrationRunner.dryRun` and `applyPending` take the connection's virtual host as a REQUIRED parameter (no default): the compiler forces every caller; the old call sites (about 18, mostly tests) are updated mechanically to pass `"/"` (allowed refactor).
7c. **Stream refusal as a type.** Add `StreamManagementResult.NotFound` (additive); `RabbitMqStreamManager.deleteStream` maps the client's `STREAM_DOES_NOT_EXIST` failure to it in ONE place (the adapter that owns that text, via a small pure function with a unit test); `StreamManagementViewModel` shows it as the existing refusal with the fixed text "The stream does not exist" so UI tests do not change; the executor treats `NotFound` on a delete as a no-op and never matches message text. `createStream` of an existing stream already answers `Success` (the client treats `STREAM_ALREADY_EXISTS` as OK, verified in bytecode): a no-op.
8. **Live test** `RealBrokerM5MigrationTest` (`data-rabbit`, `@Tag("broker")`, Testcontainers `rabbitmq:4-management` like `RealBrokerM8MigrationRequestsTest`): "Apply a migration to a real broker", "Exported topology can be applied to an empty broker" (`@gate-M5`), conflict on a queue with other arguments (400, queue unchanged), policy equal (no PUT) and different (no PUT, unchanged), read-back, delete of an absent resource (404 is a no-op), binding delete with an empty and a non-empty routing key (measures the properties key form), an exchange-to-exchange binding, typed numbers on the wire, apply twice, rerun after a failure at action 2, an action built in code with name `..` answers 405 and creates nothing. Cleans up what it creates; never reads a queue's messages.
**Echo rule (one place).** `core` gets one function `echoableName(text): Boolean` (file `EchoableName.kt` in `dev.caerbannog.core.migrations`) used by the parser's rerun message, the runner's vhost reason and the executor's reasons: a name is shown only when it is 1 to 64 characters long and is exactly `/` or consists only of `A-Z a-z 0-9 . _ -` and is not `.` or `..`; anything else (quote, backslash, newline, `<`, space, 65 characters) is never shown and the generic wording is used. M8-04's rule for an unknown ACTION name (letters and digits only) is a different thing and stays as it is.
Out: persistence and folder (`M5-08b`), desktop wiring and UX (`M5-08c`), MCP (`M5-09`), a dry run that compares with the broker (idea).

## Design notes
Ports stay in `core` (`TopologyMigrationExecutor`, `MigrationRunner`); the adapter is in `data-rabbit`; no network code in `core` or `ui`. The runner keeps its single apply loop. Failure texts are fixed, nothing is logged, nothing in this format is secret until `M8-12`. The delay for the read-back retry is injected so no test sleeps.
