# M9-05: Check against the broker: the read-only port, the plan check, the management implementation

Milestone: M9    Depends on: M9-01, M9-02 (M9-00c is NOT needed; the S-G part is cut into `M9-05b`)    Size: M

PLANNED 2026-11-15. Step 1 done 2026-11-16: the spike-dependent part is cut out (see Status). The comparison rule of this task is the one `DeclaredResourceMatcher` has today; no promise beyond it.

## Goal
For every step of a plan the app can say, from reads alone, what the broker has (absent, the same, different, unreadable) and whether the existing dry run blocks the step. The port is in `core`, the implementation in `data-rabbit` sends GET requests of the executor's allow-list only, and a 3.x connection has no such port.

## Why
Spec "Topology planner (M9)", "Check against the broker" and A6. Today's dry run (`MigrationRunner.dryRun`) says only allowed or blocked; it does not look at the broker. The owner's concept: check per step before the existing Apply.

## Scope
In:
- `core`, package `dev.caerbannog.core.migrations` (it is about actions, not about the planner only):

```kotlin
/** What an action would meet on the broker right now. Read-only: an implementation sends GET requests only and never a path under a queue's name. */
interface DeclareCheck {
    suspend fun find(action: MigrationAction): BrokerFinding
}
sealed interface BrokerFinding {
    data object Absent : BrokerFinding
    data object Same : BrokerFinding
    data object Different : BrokerFinding
    /** [reason] is one of the executor's fixed texts ("the broker did not answer", "the user is not allowed to do this", ...). */
    data class Unreadable(val reason: String) : BrokerFinding
}
```

- First commit, a pure move with no test edited: the rules inside `MigrationRunner.dryRun` and `dryRunPerAction` become a top-level pure function (`MigrationDryRunRules.evaluate(actions, hasConfigurePermission, controlLevel, vhost, userTags)`) that the runner calls, so the planner can use the same rules without a runner, a history or an executor.
- `core`, package `dev.caerbannog.core.planner`: `PlanCheck.run(plan, context, check: DeclareCheck?, onStep)` returning one `StepCheck(stepId, finding, blocked, notes)` per step. `StepFinding`: `WillBeCreated`, `AlreadyThere`, `Different`, `Missing(what)`, `NotChecked(reason)`, and for a delete step `WillBeDeleted`, `AlreadyGone`. Rules: `blocked` is the dry-run reason of that action; a step whose virtual host is not the connection's is blocked and not read; a binding whose exchange or destination is neither on the broker nor declared by an earlier step is `Missing` with the fixed sentence (the ends are probed with `find` on a declare of that name: `Absent` means it is not on the broker, `Same` or `Different` means it is, `Unreadable` makes the step `NotChecked`); an `Unreadable` is never turned into "will be created"; with no `DeclareCheck` (3.x, unknown version, not connected) the whole check is refused with the connection's reason and nothing is sent.
- `data-rabbit`: `ManagementDeclareCheck(reader: ResourceReader)`: one GET per action through `ExecutorPathAllowList` (the path of `MigrationReadRequests`), 404 is `Absent`, 200 is compared, 401 and 403 and every failure is `Unreadable` with the text of `ExecutorReasons.forReply`. Comparison: a policy with `ConflictCheck.comparePolicy`; a binding with `DeclaredResourceMatcher` (key and arguments; another binding between the same two is `Absent`); a stream is `Same` when the item is of type stream and `Different` when it is another kind of queue; a queue or exchange by `DeclaredResourceMatcher` as it is today (type and flags equal, every DECLARED argument present with the same type and value, extra arguments on the broker ignored); the measured S-G rule is `M9-05b`. A delete action is not compared: 200 means present (`Same`, so the step is `WillBeDeleted`), 404 means `Absent` (`AlreadyGone`). `HeldConnection.declareCheck: DeclareCheck?` and `StreamSource.declareCheck`, null exactly when `migrationExecutor` is null (same one `GET /api/overview`, `MigrationAccess`), wrapped by the same "still current" guard as `GuardedMigrationExecutor`.
- `core-testing`: `FakeDeclareCheck` (scripted per action, records every call). It answers only what the test scripts; it holds no broker table (the shared S-G constant is `M9-05b`).

## Design notes
One source of truth: the check reuses the executor's reader, allow-list, reasons and matchers; it adds no path and no comparison of its own. Why that is safe before S-G: the check never decides anything (scenario "The check does not decide whether a plan can be saved"); a wrong `Same` or `Different` is only a prediction, the apply keeps its own read-back and conflict rule and stops with nothing overwritten. Where the matcher ignores broker-side extras, a plan may show "Already there" for something the broker would refuse on a repeated declare; `M9-05b` measures and tightens that, and the UI wording of M9-06 must not call the result a promise. The check is sequential (one GET per step; a plan is small) and cancellable; `onStep` reports progress for `M9-06`. `core` sees only the interface; where the broker is faked: `FakeDeclareCheck` in core and acceptance tests, Ktor mock engine in data-rabbit unit tests; where it is real: `RealBrokerPlanCheckTest`.

## API shape confirmed (architect, step 2.5, 2026-11-16, round 0)
The tests are the exact API spec; the senior developer follows them. Confirmed, beyond the brief's text:
- `PlanCheck.run(plan, context, check: DeclareCheck?, onStep)` returns `PlanCheckResult` = `Refused(reason)` | `Checked(steps)`. `StepCheck(stepId, finding, blocked, notes)`. `StepFinding`: `WillBeCreated`, `AlreadyThere`, `Different`, `Missing(what)`, `NotChecked(reason)`, `WillBeDeleted`, `AlreadyGone`. Refusal order: `context.unavailableReason` first, then `PlannerTexts.NOT_CONNECTED` when the connection name is null, else the check is non-blank. Nothing is sent when refused.
- A step of another virtual host: `blocked` with the dry-run reason, finding `NotChecked`, no read and no end probe. Each binding end is probed with `check.find(DeclareExchange/DeclareQueue(name, vhost))` unless an earlier step of the plan declares it. A `Different` step carries notes that contain "stop" and "overwritten" (applying would stop there, nothing overwritten); this is a fixed sentence, see Owner review list.
- `MigrationDryRunRules.evaluate(actions, hasConfigurePermission, controlLevel, vhost, userTags)`: a pure extraction, both precedence orders kept, parity with `MigrationRunner.dryRun` over 324 combinations. The pure move is the first commit after F5 and edits no existing test.
- `ManagementDeclareCheck`: internal constructor over `ResourceReader`, an `overClient` test seam, `NOT_A_REQUEST` (an `Unreadable`) for names that cannot be made into a request, a binding delete is `Same` only when `BindingList.plain` has that routing key, 400 and every other failure is `Unreadable`.
- `MigrationAccess.declareCheck`, `RabbitMqHeldConnection.declareCheck`, `HeldConnection.declareCheck: DeclareCheck?` (default null), `StreamSource.declareCheck`; the closed-connection guard answers `Unreadable("Connection closed")`. `FakeDeclareCheck` and `FakeConnectionGateway.setDeclareCheck` as in core-testing. `ManagementDeclareCheck.kt` joins the allowed files of `OverClientGuardTest`.
