# M10-02: Secret guard, access gateway and the Who am I tab

Milestone: M10    Depends on: M10-00 (S-A, S-D, S-N, S-O), M10-01 for the screen    Size: M

## Goal
The Access screen opens from the connection that is held and shows the connection user, its tags and the virtual hosts the broker lists, read only, with all states; and one core component, `SecretGuard`, exists that every later Access slice, the logs and the MCP server use to keep secrets out.

## Why
Spec "Access view (M10)", goal 1 and "Redaction rules"; "Screens and UX" (Topology read-only rule, owner decision Q15); 3.x rule (M8). The first slice that works end to end; the guard comes first because every other slice depends on it.

## Scope
In, in three commits, each green:
1. **`SecretGuard` in `core`** (pure, no `java.*`): the allow-list of connection and channel fields, the shape scan (JWT, `Bearer `, `scheme://user:password@`, `password=`, `secret=`, `token=`), the held-password scan (the holder passes the secret in for the scan; the guard never stores it), the "hidden" replacement with a counter, the mapped error reasons. Unit tests first, with the redaction fixtures of spike S-N. Property test: for random strings built from a secret plus noise, no output contains the secret or its segments longer than 6 characters.
2. **`AccessGateway` interface in `core`** (`whoAmI()`, `virtualHosts()`; later slices add their calls) with a fake in `core-testing`, and the `data-rabbit` implementation over the existing management client (GET only, the profile's TLS setting, no new HTTP stack). Typed results: `Loaded`, `NoManagementTag`, `NotAuthorised`, `Unreachable`, `Unexpected` (reason only, never a body) and, decided at step 2, `NotOffered` (a known 3.x broker; see "Architect decisions at step 2"). 3.x connections: the gateway refuses and sends nothing (AQ6).
3. **`AccessViewModel` in `core` and the screen shell in `ui`**: state in, events out; the tab Who am I; the other tabs are present but empty ("not built yet" is not shown to users: tabs appear as their slices land). Navigation entry per AQ1. Refresh through the shared refresh driver (D3), only while shown; stale state and the "Connection lost" banner as D2; "Not encrypted" banner on a plain profile; no credential is sent before the connection is held (reuse the held-connection rule).
Out: permissions, sign-in tab, clients, MCP.

## Design notes
`core/access` (new package), `data-rabbit` gateway next to the management client, `ui/access`, wiring in `desktopApp` composition root. No broker or Ktor type in `core` or `ui`. The guard is called at the gateway boundary (data leaves `data-rabbit` already redacted), not only in the UI, so a later screen or tool cannot forget it. Fakes behind the same interface. Unit tests with fakes; one live test of the gateway against the broker of `RealBrokerAccessSpikeTest`'s fixture style is left to `M10-09`.

## Architect decisions at step 2 (2026-11-25, branch `M10-02-secret-guard-and-who-am-i`)
Answers to the test developer's questions after commit `3e44f842`. None needs the owner except where said.

1. **Held secret below 7 characters.** `MIN_HELD_SEGMENT = 7` stands for secrets of 7 or more (any 7-character window of the secret inside a value hides the whole value). A held secret shorter than 7 characters hides a value only when the value equals it exactly (case-sensitive); inside longer text only the shape scan applies. Reason: a shorter window hides ordinary names; the real held secret here is a JWT. Spec "Redaction rules", rule 1, updated. Test scope: add to `SecretGuardTest` "a held secret of 6 characters hides only an equal value" and "a held secret of 7 characters hides a value that contains it"; the property test keeps its 7-character window.
2. **3.x result: add a sixth result type.** `AccessResult.NotOffered` (a `data object`). Reason: `Unexpected(NEEDS_4X)` would make the view model match on text (a smell) and would let the notice leak into a Failed message, but the spec says "needs a 4.x broker" appears only in the Connections notice. Test developer's scope, exactly: (a) `AccessModel.kt`: add `data object NotOffered : AccessResult<Nothing>`; `UnavailableAccessGateway` returns it; the doc comment of `AccessResult` lists six types; (b) `ManagementAccessGatewayTest`, the 3.x test (line about 198): assert `AccessResult.NotOffered` instead of `Unexpected(AccessTexts.NEEDS_4X)`; (c) `AccessViewModelTest`: one new test, a gateway that answers `NotOffered` makes the state leave Access with `leaveNotice == AccessTexts.NEEDS_4X` and never `Failed`; (d) `FakeAccessGateway`: allow it to be told to answer `NotOffered`. `AccessTexts.NEEDS_4X` stays where it is. The existing 3.x view model tests that start from the profile stay as they are.
3. **Unknown broker version:** confirmed. The gateway asks; only a known 3.x refuses (same rule as `isMigrationSourceOnly`).
4. **Channel allow-list:** confirmed and now in the spec (rule 2): `name`, `user`, `vhost`, `node`, `state`, `connection_details.name`, `connection_details.peer_host`, `connection_details.peer_port`, checked against `s-e-channels-A.json`. Not kept: `user_who_performed_action` (equals `user`), counters, `garbage_collection`, `reductions` and the rest. `M10-06` names its consumer fields one by one when it starts (no widening here).
5. **Plain 401 on `whoami`:** confirmed. The Who am I tab shows the approved sentence "The broker refused the sign-in." (the first sentence of the approved refusal banner) with Retry; the chip wording is `M10-10` (for a token profile, a refusal of a data call on a held connection follows `M10-10`). No owner input needed.
6. **Failed `whoami` (any other error):** the screen shows "The user could not be read. Broker text: <mapped reason>" with Retry, no user, no tags and no virtual host list. It is the same template as the approved "The virtual hosts could not be read. Broker text: HTTP 500". The mockup now has the frame "Who am I: error (the user cannot be read)" (section `who-user-error`) marked "proposed"; the owner sees it with the mockup review, and the build may start on it (a wording change later is one constant, `AccessTexts`). Add `AccessTexts.USER_ERROR = "The user could not be read."` and a test "whoami fails with HTTP 500: Failed with that text and Retry, no virtual host call result shown".
7. **Order of the virtual host list:** the text is right: the connection's virtual host first, then the rest alphabetical. The mockup rows are fixed (`/`, `/billing`, `/orders`, `/staging`); the tests that follow the text stand.
8. **Mid-session gap (whoami succeeded, then `virtualHosts` is refused):** `NoManagementTag` from either call: the whole screen becomes Locked (as the no-tag state), and the earlier user and tags are removed (they may be stale). `NotAuthorised` from either call: the screen keeps the last data dimmed and marked stale, shows the refusal banner "The broker refused the sign-in." with Retry (the same as the connection-lost treatment, D2; `M10-10` adds the chip). `Unreachable`: D2 (lost connection). `Unexpected` on `virtualHosts` only: the user and tags stay, the list shows the error (already tested). New tests in `AccessViewModelTest`: "whoami ok then virtual hosts say no management tag: Locked, no user shown" and "whoami ok then virtual hosts are refused: last data stale with the refusal banner and Retry".
