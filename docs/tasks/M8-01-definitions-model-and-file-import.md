# Definitions model and file import (3.x export)

Milestone: M8    Depends on: M8-00 (done)    Size: M

## Goal
A `definitions.json` exported from RabbitMQ 3.x (or 4.x) can be read into a typed `core` model in which no secret is readable by accident (user hashes are redacting pass-through values, parameter values are dropped), a file that is not a definitions export is rejected with a typed reason, a per-virtual-host export (no vhost names in it) is accepted as an "unassigned" draft that cannot be analysed until the user names the virtual host, and a file can be loaded from a path as text with a size limit.

## Why
Spec "Migrating from RabbitMQ 3.x (M8)", decision 1 (file source), "3.x as a read-only source" (secrets bullet, changed by P2) and the measured export shape (S-A). The parser is shared with the live source (`M8-02`), the analyzer (`M8-03`), the generator (`M8-05`) and the hash comparison (`M8-12`).

## Scope
In (all in module `core`, package `dev.caerbannog.core.migrate3x`, `commonMain`, no JVM-only types):

1. **Model** (immutable data classes and sealed types; file `DefinitionsModel.kt`):
   - `DefinitionsDocument(sourceVersion: String?, virtualHosts, queues, exchanges, bindings, policies, operatorPolicies, users, permissions, topicPermissions, otherParameters: List<UnparsedParameter>)`, every list a `List`, never null.
   - `DefinitionsDocument.origin: DefinitionsOrigin` = `FullExport | SingleVirtualHost(assignedName: String)`. For `SingleVirtualHost` the lists `virtualHosts`, `users`, `permissions` and `topicPermissions` are ALWAYS empty (the per-vhost export holds none of them, measured S-A), and consumers must say so (the report and the access migration: see "Per-virtual-host export" below).
   - `sourceVersion`: `rabbitmq_version`, else `rabbit_version`, else `product_version`, else null (the three are the measured keys).
   - `VirtualHostDefinition(name, description: String, tags: List<String>, defaultQueueType: String?)`. Description and tags come from `metadata` when present, else the top-level keys, else empty; `default_queue_type` from `metadata`, else top level, else null (3.13 puts it in both, measured).
   - `QueueDefinition(vhost, name, durable = true, autoDelete = false, type: QueueKind, arguments: Map<String, ArgumentValue>)`. `QueueKind` = `Classic | Quorum | Stream | Other(name)`. Type rule: a top-level `type` key (4.x exports) wins, else `arguments["x-queue-type"]`, else `Classic` (3.13 entries have NO `type` key, measured S-A). Unknown name gives `Other(name)`, never an error.
   - `ExchangeDefinition(vhost, name, type: String, durable = true, autoDelete = false, internal = false, arguments)`.
   - `BindingDefinition(vhost, source, destination, destinationKind: BindingTarget (Queue | Exchange), routingKey = "", arguments)`; exchange-to-exchange bindings are kept (measured in the fixture).
   - `PolicyDefinition(vhost, name, pattern, applyTo = "all", priority = 0, definition: Map<String, ArgumentValue>)`; `OperatorPolicyDefinition` the same fields, read from the `parameters` entries with `component == "operator_policy"` (NOT a top-level key, measured). Its `value` holds `pattern`, `apply-to`, `priority`, `definition`.
   - `UserDefinition(name, passwordHash: SecretValue?, hashingAlgorithm: String?, tags: List<String>, limits: Map<String, ArgumentValue>)`. `tags` is an array (measured); a comma-separated string is tolerated by splitting on commas (older exports, UNVERIFIED, tolerance only). Absent or null `password_hash` gives null; any algorithm name is kept as text (3.13 accepts any).
   - `PermissionDefinition(vhost, user, configure, read, write)`, `TopicPermissionDefinition(vhost, user, exchange, write, read)`.
   - `UnparsedParameter(vhost: String?, component: String, name: String)`: one per `parameters` entry that is not an operator policy (shovel, federation, others) and one per `global_parameters` entry (vhost null, component `"global"`). It has NO value field: the value is never read into the model (a shovel or federation URI carries a clear password, measured S-A, S-F).
2. **`ArgumentValue`** (file `ArgumentValue.kt`), sealed: `Text(String)`, `Whole(Long)`, `Decimal(Double)`, `Flag(Boolean)`, `Items(List<ArgumentValue>)`, `Table(Map<String, ArgumentValue>)`, `Nothing` (JSON null). A JSON number without fraction or exponent that fits a `Long` is `Whole`, otherwise `Decimal`. Used for queue, exchange and binding arguments, policy definitions and user limits. No `kotlinx.serialization` type appears in the public model or in the parser's signature.
3. **`SecretValue`** (file `SecretValue.kt`), rules, all tested:
   - A plain `class` (NOT a data class, so no generated `toString`, `equals`, `hashCode`, `copy` or `componentN`), private constructor plus `SecretValue.of(String)`.
   - `toString()` returns the constant `"SecretValue(***)"`. Never a length, prefix or hash of the content.
   - `equals` and `hashCode` are NOT overridden (identity), so no content-derived value leaks through a hash set or a map key; two parses of the same file give two different instances. Comparison for `M8-12` goes through `fun matches(other: SecretValue): Boolean` (content compare).
   - The only way to read the text is `fun expose(): String`, documented "only for the migration file writer (`M8-05`) and the comparison (`M8-12`); never log, show or serialize". Not `@Serializable`, no `Json` support, no `CharSequence`, no `Comparable`.
   - Because Kotlin string templates call `toString()`, `"$user"`, `"${user.passwordHash}"` and a `UserDefinition.toString()` must contain `SecretValue(***)` and no hash character sequence. No `String` field anywhere in the model holds a hash.
4. **Parser** (`DefinitionsParser.kt`): `object DefinitionsParser { fun parse(text: String): DefinitionsParseResult }`, a pure function, never throws for bad input.
   - `DefinitionsParseResult` = `Parsed(document)` | `Rejected(reason: DefinitionsRejection)`.
   - `DefinitionsRejection` (sealed, each with a fixed `message: String`, which never contains any part of the input; kotlinx exception messages quote the input and MUST NOT be copied):
     | Case | When | message |
     | --- | --- | --- |
     | `NotJson` | text is not valid JSON (including empty text) | `The file is not valid JSON` |
     | `NoDefinitions` | the JSON value is an empty object `{}` | `The file has no definitions` |
     | `NotDefinitionsFile` | the JSON value is an array or a scalar, or an object that has none of the keys `queues, exchanges, bindings, policies, parameters, users, vhosts, permissions, topic_permissions, rabbit_version, rabbitmq_version` (for example a migration file) | `The file is not a definitions file` |
     | `Malformed(section)` | a mix of entries with and without `vhost` in `queues`, `exchanges`, `bindings`, `policies` or `parameters`, or entries without `vhost` in a file that also has `users`, `vhosts`, `permissions` or `topic_permissions` entries, or a known section is not an array (or `metadata`, `definition`, `arguments`, `limits`, `value` is not an object), or an entry lacks a required key (below) | `The file is not a definitions file: the section "<section>" is malformed` (section name only, never content) |
   - Required keys: queue, exchange, policy, user, vhost `name`; binding `source`, `destination`, `destination_type`, `vhost`; policy `pattern` and `vhost`; permission and topic permission `user`, `vhost` and the regexes (`configure`, `read`, `write`; topic: `exchange`, `write`, `read`); every entry other than the vhost list itself needs `vhost`. Everything else is optional with the defaults in the model above.
   - **Nesting limit (required, decided in round 0, untrusted input).** `ArgumentValue` conversion is recursive, so it is depth-limited: `Items` and `Table` may nest at most `MAX_ARGUMENT_DEPTH = 32` levels (the top-level argument, definition or limits map is level 0; a list or table inside it is level 1). A value nested deeper makes the whole file `Malformed(section)` of the section that holds it (`queues`, `exchanges`, `bindings`, `policies`, `users`, `parameters`), with the usual fixed message, never a stack overflow, never a truncated value. The JSON tree parse itself is not recursive for this purpose (kotlinx-serialization reads the tree with its own deep-recursion handling), so the guard is on the conversion only; do not catch `StackOverflowError`.
   - **Missing sections** (any of the top-level lists absent, null or `[]`) give an empty list and a `Parsed` document; so a file with only `{"queues": []}` or only `{"rabbit_version": "3.13.7"}` is `Parsed` and empty (not `NoDefinitions`, which is only `{}`).
   - **Unknown keys** at any level are ignored (`product_name`, a future `metadata` key, unknown queue fields). Unknown top-level sections are ignored.
   - Duplicates are kept as they come (the broker allows none; the parser does not judge).
   - Accepts 3.x and 4.x exports alike (a 4.x export adds `type` to every queue); no version gate.
   - Parameter values and global parameter values are never converted into the model (see `UnparsedParameter`), and operator policy values are read only through the typed fields.
   - **Per-virtual-host export** (owner decision 2026-11-09, option (b): accept and ask for the name). A per-vhost export (what the management UI downloads for one vhost; measured `definitions-3.13-vhost-v1.json`) has no `vhost` key on queues, exchanges, bindings, policies and parameters, and no `users`, `vhosts`, `permissions`, `topic_permissions`. Detection: at least one entry without `vhost` in those five sections, none with, and no entries in `users`, `vhosts`, `permissions`, `topic_permissions`. An export with all five sections empty or absent is NOT this case (it is an empty `FullExport`).
   - Names fixed (the tests use them; build exactly these): `UnassignedDefinitions.sourceVersion: String?`, `queueCount`, `exchangeCount`, `bindingCount`, `policyCount: Int`; `DefinitionsRejection.message: String`; `JvmDefinitionsFileLoader(maxBytes: Long = MAX_DEFINITIONS_FILE_BYTES)`.
   - The types make it impossible to analyse such a file by accident, without a runtime flag: `DefinitionsParseResult` is `Parsed(document: DefinitionsDocument)` | `NeedsVirtualHost(draft: UnassignedDefinitions)` | `Rejected(reason)`. `UnassignedDefinitions` is NOT a `DefinitionsDocument` and has none of its lists as public API (it may expose counts of queues, exchanges, bindings, policies for the prompt text and `sourceVersion`). The analyzer (`M8-03`), the generator (`M8-05`) and the live source take `DefinitionsDocument` only, so an unassigned draft does not compile where a document is expected.
   - `UnassignedDefinitions.assignVirtualHost(name: String): VirtualHostAssignment`, a pure function, `VirtualHostAssignment` = `Assigned(document)` (every queue, exchange, binding, policy and operator policy carries `name` as its `vhost`, `origin = SingleVirtualHost(name)`, `virtualHosts` empty) | `InvalidName(reason: String)`. Validation, deliberately minimal: not blank, and no control characters (`Char.isISOControl`); no trimming, no length limit, no character whitelist. RabbitMQ's own virtual host name rules (length, allowed characters) are UNVERIFIED; do not invent them here (a later spike may add them). `InvalidName` reasons are fixed texts and never echo the typed name.
   - Why `virtualHosts` stays empty: declaring the virtual host belongs to the access migration (`M8-12`), and this file cannot say how the source vhost was configured (description, tags). The access migration for such a document is empty, and it says why: "This file is an export of one virtual host and holds no users, virtual hosts or permissions; the virtual host \"<name>\" must already exist on the 4.x broker" (text owned by `M8-05`/`M8-03`).
   - The prompt for the name is UI and belongs to `M8-06`.
5. **Large file.** `parse` takes the whole text as one `String` (kotlinx-serialization 1.7.3 streaming decode is JVM-only and `core` is `commonMain`). The rule: the parser makes at most one JSON tree of the text, converts it section by section into the typed model, never copies the text (no `trim`, `replace`, `lines`, `split` of the whole input), and returns a document that references neither the text nor the tree (arguments are copied into `ArgumentValue`), so both are collectable as soon as `parse` returns. A 20 MB file must parse in `core`'s default `jvmTest` heap (no `maxHeapSize` bump for this test; if it needs one, stop and tell the architect, do not raise it silently).
6. **File loading** (what the brief called "a file chooser action that only loads text"; the dialog itself is `M8-06`):
   - In `core`: `fun interface DefinitionsFileLoader { suspend fun load(path: String): FileLoadResult }` and `FileLoadResult` = `Loaded(text: String)` | `Unreadable(reason: String)` | `TooLarge(bytes: Long, limit: Long)`, and the constant `MAX_DEFINITIONS_FILE_BYTES = 64L * 1024 * 1024`.
   - In `data-rabbit` (where the other file-backed repository implementations live): `JvmDefinitionsFileLoader`, reads UTF-8 (a leading BOM is stripped; a malformed byte sequence gives `Unreadable`), checks the file size BEFORE reading, runs on `Dispatchers.IO`, never writes. An `Unreadable` reason never includes file content.
   - A fake loader for the acceptance steps lives in `core-testing`.

Out: the analyzer and report (`M8-03`), live fetch and 3.x detection (`M8-02`), the migration widening (`M8-04`), generation (`M8-05`), the screen, the native file dialog and the Migrate-from-3.x entry point (`M8-06`), the user hash comparison (`M8-12`), any MCP tool, rendering the model as JSON (no serializer for the model exists in this task: the report serializer of `M8-03` works from its own types), storing a parsed document on disk, the prompt for the virtual host name (`M8-06`), what the generator does with an unassigned or single-vhost document (`M8-05`), global parameters and shovel or federation parameter values (dropped), `@Serializable` on any model type, any new Gradle dependency.

## Design notes
`core` only for model and parser; the file reader implementation in `data-rabbit` behind the `core` interface, the fake in `core-testing`. Follow `MigrationParser` conventions: `Json.parseToJsonElement` and `JsonObject` access inside the parser only, typed errors, never an exception from `parse`. Catch `SerializationException` and `IllegalArgumentException` narrowly around the tree parse (as `MigrationParser` does), map both to `NotJson`; do not catch `Throwable`. Split the parser into small private functions per section (queues, exchanges, ..., users), each returning the list or a `Malformed(section)`; use a small private `JsonObject` reader helper for required, optional-with-default and typed access instead of repeating null checks. Typed arguments matter because the current `DeclareQueue.arguments` is `Map<String,String>` (see `M8-04`). The document is immutable and holds no reference to the tree. The `SecretValue` lives in `core` and is reused by `M8-05` (migration action `DeclareUser`) and `M8-12`; do not put it in a migrations package.

## Open points
1. Virtual host name rules of RabbitMQ (maximum length, forbidden characters) are UNVERIFIED; validation here is blank and control characters only. Whether a name that does not exist on the 4.x broker is handled is the job of the migration apply (`M8-05`/`M8-12`), not of the parser.
2. Shape of a real export that holds a Shovel and of 3.x versions older than 3.13 (tags as a string) is UNVERIFIED; the parser tolerates, tests use the measured 3.13 shape plus the one hand-built shovel fixture, which is labelled as hand-built.

## Spike findings (M8-00, 2026-11-09)
Measured shape of the 3.13 export (`M8-00-spike-results.md` S-A, fixtures in `data-rabbit/src/test/resources/fixtures/m8-00/`): queue entries have NO `type` key (the type is `arguments.x-queue-type`, missing means classic; a 4.x export adds `type`); operator policies are `parameters` entries with `component: operator_policy`, not a top-level key; users have `password_hash`, `hashing_algorithm` (any name on 3.13), `tags` as an array, `limits`; vhost `metadata` holds `description`, `tags`, `default_queue_type` (3.13 also at top level); `guest` is exported; the per-vhost export holds no users, vhosts or permissions and its entries carry no `vhost` key, so the live source uses the full export. Parameter values (federation and shovel URIs) can hold passwords in clear and are dropped by the parser; this includes a 4.x `GET /api/definitions` read for the user hash comparison (`M8-12`) and a 3.x export taken while a Shovel exists. `@needs-spike` is gone from the scenarios of this brief.
