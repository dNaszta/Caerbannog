## Goal
The wizard has a Stream kind. Its form asks for a name and offers the tick "Also create its response stream (DLN)", off by default; with the tick a second stream with a suggested name is added. The pair is shown as a pair in the step list and linked in the review graph, also after the file is saved and opened again, as long as the name follows the rule.

## Why
Owner decisions O9 ("DLN ... is a response stream which is one 'pair' of the 'request'"), O10 ("Stream pair - it is optional"), O11 (suffix by default). Spec "Topology planner (M9)", "Streams and the response stream", A11.

## Scope
In:

## API shape confirmed (architect, step 2.5, 2026-11-16)
The tests are the exact API; the senior developer builds to them. Confirmed, with the decisions where the tests left room:

1. `StreamForm(name, withResponse = false, responseName: String? = null)`: `null` follows the stream name, any string (even empty) is "edited by hand". `suggestedResponseName(ctx)` = `PlanNaming.derived(name, DerivedWord.DLN, ctx.namingStyle)`, or "" while `name` is empty. `effectiveResponseName(ctx)` = `responseName ?: suggestedResponseName(ctx)`.
2. Problems on the fields `name` and `responseName`: `STREAM_NAME_MISSING` "Give the stream a name", `RESPONSE_NAME_MISSING` "Give the response stream a name", equal names "The response stream needs a name of its own" (`RESPONSE_NAME_SAME`), a name the plan declares as a queue gives `PlannerTexts.queueAndStreamOfOneName(name)` on that field. A response name that follows an empty stream name gives only the `name` problem. Tick off: `responseName` is not checked and has no hint. Hints are `FieldHint("responseName", ...)` (the existing naming hint), never for a name the broker already has (same rule as `name`). `actions` is empty while any problem exists.
3. `PlanPairs.responseOf(plan): Map<Int, Int>` (response step id to request step id), core, pure. Only `DeclareStream` steps count (delete, queue, exchange are never a base or a response). Two candidates for one request both map to it. Iteration order: plan order of the response step (use a `LinkedHashMap`), so links are deterministic.
4. `PlannerTexts`: `RESPONSE_STREAM_TICK`, `RESPONSE_STREAM_NAME_LABEL` ("Response stream (DLN) name"), `RESPONSE_STREAM_NOTE` (the neutral sentence; the guard test names no broker, message, move or write), `RESPONSE_LINK_LABEL` "response (DLN)", `responseStreamOf(request)` "Response stream (DLN) of X" with the existing echo rule (hostile or empty name gives "Response stream (DLN)"), `kindDescription("Stream")` = "Optionally with its response stream (DLN)", `BUILT_KINDS` = Queue, Exchange, Binding, Stream. `PlannerState.responseStreamLine(stepId): String?` (null for a step that is not a recognised response stream).
