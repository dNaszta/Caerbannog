# Live 3.x source on the Migrate-from-3.x screen

Milestone: M8    Depends on: M8-02 (02a and 02b built, verified and merged), M8-06a, M8-06b (merged)    Size: M (one developer, 2 to 3 days)

Brief made exact against main 99648cc by the architect (team loop step 1, round 0, 2026-11-10). Owner decisions F4 (option B) and F8 (option B) are decided.

## Goal
The user can analyse the connected RabbitMQ 3.x broker from the Migrate-from-3.x screen (source picker, locked source card, file import offered as a button when the user may not export), starts it from the 3.x connection popup, and sees the navigation reason once, not under every disabled item (F4). The 3.x pill on a profile card shows only while that profile is Connected (F8).

## Why
Spec "Migrating from RabbitMQ 3.x (M8)", decision 1 (live source or file), `docs/tasks/M8-06-report-and-review-ui.md` cut table. M8-02 built the live read (`analyseLive`, `DefinitionsSource`); nothing on screen uses it yet.

## Decided signatures (all in `core` unless said)

Types (`core/migrate3x`, new file `LiveSourceOnScreen.kt`):

```kotlin
enum class SourceKind { File, Live }

/** What the screen may read live right now; null = no readable 3.x connection is held. Read only: DefinitionsSource has no write method. */
interface LiveSourceProvider {
    val current: StateFlow<DefinitionsSource?>
    companion object { val None: LiveSourceProvider }          // current = MutableStateFlow(null), the default of tests and of a screen without a connection
}

sealed interface SourceOption {
    val label: String
    data object File : SourceOption                             // label "Definitions file"
    data class Live(val connectionName: String) : SourceOption  // label "Live connection: <name>"
    data class LiveDisabled(val reason: String) : SourceOption  // label "Live connection", reason = MigrateFromThreeTexts.LIVE_NOT_AVAILABLE
}

/** [selected] is Live only while a Live option is offered (a vanished 3.x connection turns it back into File). */
data class SourcePicker(val selected: SourceKind, val options: List<SourceOption>)
```

Not a `fun interface`: the picker must follow the connection while the screen is open (the user may connect from the chip popup), so the provider is a `StateFlow`. The real one is built in core, so it is unit tested without desktopApp:

```kotlin
/** core/connections: Connected link + held StreamSource + session status Done(MigrationSource) -> that source's definitionsSource, else null. */
class HeldLiveSourceProvider(active: ActiveConnection, session: ConnectionSession, scope: CoroutineScope) : LiveSourceProvider
internal fun liveSourceOf(link: LinkState, source: StreamSource?, sessionState: SessionState): DefinitionsSource?   // the pure rule
```

`HeldAnalysis` gets `val kind: SourceKind = SourceKind.File` (last constructor parameter, default keeps every file test as it is); `analyseLive(...)` builds it with `SourceKind.Live` and the connection name as `fileLabel`. The kind lives in the held analysis because the analysis outlives the view model (D1).

`MigrateFromThreeViewModel` (constructor adds `liveSource: LiveSourceProvider` after `folders`, default `LiveSourceProvider.None`; `analysisDispatcher` stays last):

- Existing states and their tags stay as they are. `ChooseSource` stays a `data object` (existing tests rely on it); the picker is a second flow: `val picker: StateFlow<SourcePicker>`, derived from `liveSource.current` and the chosen kind (`combine(...).stateIn(scope, Eagerly, initial)`), shown by the screen inside `ChooseSource`.
- New states: `LoadingLive(connectionName: String)` (the live read runs; `cancelLoading()` works for it too and goes back to `ChooseSource`), `CannotExport(connectionName: String, text: String)` (text = `LiveSourceTexts.CANNOT_EXPORT`), `LiveFailed(connectionName: String, text: String)` (`Unreachable` gives `LiveSourceTexts.unreachable(name)`, `Failed` gives its fixed `text`). Never a body, a URL or a credential: the texts are the fixed ones of `LiveSourceTexts` (merged in M8-02a, reuse, add none); the VM passes the outcome's text on and the real `LiveDefinitionsSource` guarantees it is fixed (a sentinel test proves it, see Acceptance).
- New events: `chooseSource(kind: SourceKind)` (selects the kind of the picker; in `ChooseSource`, `Rejected`, `CannotExport` and `LiveFailed` it also returns to `ChooseSource`; ignored in `LoadingLive`, `Loading`, `NeedsVirtualHost` and `Report`; `Live` is ignored while no live source is offered), `analyseLive()` (from any state except `LoadingLive`; ignored while `liveSource.current` is null: the picker already shows why).
- `analyseLive()`: cancels the running job, drops the review locals like `open` does, shows `LoadingLive(name)`, then `analyseLive(source, analysisDispatcher)` (F7: the same injected dispatcher as the file path), then `ensureActive()` and maps: `Analysed` to the report through the same private presenting step as the file path (`holder.hold`, filters reset), `OfferFileImport(text)` to `CannotExport`, `Unreachable` and `Failed` to `LiveFailed`. A result that arrives after `reset()`, `cancelLoading()` or a newer analysis is dropped (its job was cancelled, `epoch` as today). The second analysis replaces the first and the decisions of the first.
- The view model observes `liveSource.current` and calls the existing `rebuild()` when it changes, so the source card text follows the connection.
- `ReportView` gets `val source: SourceCardView` (existing `fileLabel` stays and equals the label for a file): `data class SourceCardView(val kind: SourceKind, val label: String, val locked: Boolean, val lockText: String?, val canAnalyseAgain: Boolean)`. Rule (pure, in `ReportViewBuilder.build`, new parameter `liveConnectionName: String? = null`): File gives `locked = false`; Live gives `locked = true`, `lockText = "read only"`, `label = name` while `liveConnectionName == held.fileLabel`, else `label = "from <name> (disconnected)"` and `canAnalyseAgain = false`.
- Texts (add to `MigrateFromThreeTexts`): `LIVE_NOT_AVAILABLE = "Connect to a RabbitMQ 3.x broker to read it live"`, `SOURCE_FILE = "Definitions file"`, `LIVE_DISABLED = "Live connection"`, `liveOption(name) = "Live connection: $name"`, `READ_ONLY = "read only"`, `liveDisconnected(name) = "from $name (disconnected)"`, `ANALYSE_LIVE = "Analyse live connection"`, `ANALYSE_AGAIN = "Analyse again"`, `TRY_AGAIN = "Try again"`, `liveLoading(name) = "Reading and analysing $name"`, `LIVE_LOADING_HINT = "Reading the broker can take a few seconds per virtual host. Nothing on it is changed."`, `INFO_LINE` (see Open points).

## Design notes
State in, events out; decisions (which options, which reason, which state, which card text, which pill) in `core`, composables thin. The held connection is still one (D1): the picker never offers to connect, it only reads the held connection through `LiveSourceProvider`. The analysis lives in `AnalysisHolder`, not in the view model. The live fetch can take up to 5 s per vhost with a fresh queue (02a bound): `LoadingLive` has Cancel (`cancelLoading()`). The pause of the storage-version scan is `liveSourcePause` inside `ActiveConnection` (already wired in `guardedSource`); this task passes nothing and never calls `delay` itself. Broker faked: `FakeThreeXReads` behind the real `LiveDefinitionsSource`; no real broker in this task (`RealBrokerM8LiveSourceTest` stays green, untouched).

## MCP
None (UI-only). Reason: the live read is reachable by an agent only through the app's own screens; an MCP tool that analyses or forwards would add a write-adjacent path to a 3.x broker, and the spec forbids a Shovel tool. An analysis tool is a separate decision (M8-06b already records no tool).

## Open points

It needs no connection and sends nothing to any broker." With a live source this is wrong. Options: (a) keep it for the file option and show "This screen only reads from the connected 3.x broker, with GET requests. It changes nothing on it." for the live option; (b) one line for both: "This screen only reads a file or the connected 3.x broker. It sends nothing that changes any broker."; (c) keep as is. Recommendation (b), constant `MigrateFromThreeTexts.INFO_LINE`. Also new texts the owner has not seen: "Analyse live connection", "Analyse again", "Try again", the live loading hint (all listed in the mockup notes).
- Technical, decided by the architect: "Analyse again" only while the same connection is Connected; the popup entry does not change a report that is on screen; the picker offers no "connect" action.
